# Что нужно реализовать для нового проекта V2

Ниже — практический список работ, чтобы довести новый AI-агент до уровня курсового по ТЗ.

## 1) Данные и форматы (обязательно)

1. Реальные входные наборы:
   - MIIS XML (учтённые сети, колодцы, охранные зоны).
   - Растры/изображения аэрогеофизики (магнитка).
   - SEG-Y (ГРЛ) и ВЭЗ-профили.
2. Единый контракт загрузки:
   - валидация обязательных полей;
   - журнал ошибок импорта (какие данные не приняты и почему).

## 2) Пространственная точность и трансформация

1. Калибровка по контрольным точкам (>=50).
2. Протокол расчёта СКО и сохранение отчёта по привязке.
3. Авто-отбраковка запусков при СКО > 0.18 м.

## 3) Детекция и признаки

1. Выделение аномалий на магниторазведке:
   - median, Canny, Hough, пост-фильтрация линий.
2. Интеграция SEG-Y:
   - признаки гипербол;
   - оценка глубины труб.
3. Интеграция ВЭЗ:
   - градиенты ρ и индикаторы увлажнения/муфт.

## 4) Модели ML

1. UtilityTypeIdentifier (RF, 14 признаков) — обучение на реальных метках.
2. DamageRiskClassifier (CatBoost) — обучение на исторических кейсах.
3. Контроль качества:
   - confusion matrix;
   - recall по критическим кейсам;
   - AUC/F1.

## 5) Нормативная логика и валидация

1. Rulebook `R01..R12` с ссылками на СП/ГОСТ.
2. Автоматические проверки:
   - пороги 30/50 нТл;
   - буферы 2.5 м и охранные зоны 3–10 м;
   - строгие условия классов 89/62/12.

## 6) Риск и рекомендации

1. Расчёт `R = P(comm) × P(damage|depth) × W`.
2. Правила назначения уточнения:
   - шурф №ШШ-247;
   - ГРЛ ЛОМА-5;
   - видеозондирование.
3. Привязка рекомендаций к глубине и типу сети.

## 7) Отчётность и выгрузки

1. Полный MIIS XML по структуре города.
2. DXF схема с слоями и стилями по категориям риска.
3. PDF акт в формате Приложения №5 СП 47.13330.2016:
   - таблицы расчётов;
   - приложения;
   - схема привязки к ближайшим объектам.

## 8) Инфраструктура и эксплуатация

1. PostGIS/pgPointCloud хранилище.
2. Миграции (Alembic), аудит и версионирование.
3. CI/CD: lint + typecheck + tests.
4. Безопасность API: auth + rate limit + audit log.

## Что нужно от заказчика/студента для полного закрытия ТЗ

1. Доступ к реальным данным (или репрезентативным обезличенным наборам).
2. Формальный шаблон акта (образец Приложения №5 в требуемом виде).
3. Набор экспертных разметок для оценки метрик качества.
4. Подтверждённые правила интеграции в ГИС-приёмник (структура MIIS-полей).
