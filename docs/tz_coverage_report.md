## 2. Что реализовано частично

1. **ML-модели как production-контур**
   - Есть интерфейсы и загрузка моделей.
   - Но fallback-режим всё ещё эвристический, нет полного MLOps контура.

2. **SEG-Y анализ**
   - Есть извлечение признаков.
   - Алгоритм гипербол пока упрощён (инженерный baseline, не финальная научная модель).

3. **Нормативы**
   - Добавлен набор `R01..R12`.
   - Требуется формальная трассировка `rule ↔ пункт СП` в виде отдельного нормативного реестра.

4. **История запусков**
   - Реализована через file-based store (`.cache/web/run_history.json`).
   - Для production лучше вынести в БД.

---

## 3. Что пока не реализовано (gap)

1. **Полноценный слой PostGIS/pgPointCloud**
   - Нет завершённого слоя репозиториев, миграций, API к БД.

2. **CI/CD и quality gates**
   - Нет полноценного pipeline с линтингом/типизацией/автотестами в GitHub Actions.

3. **Безопасность web-слоя уровня production**
   - Нет auth, rate limiting, audit trail пользователей.

4. **Оркестрация длинных задач уровня production**
   - Асинхронность реализована in-process (ThreadPool).
   - Для тяжёлой нагрузки нужен внешний брокер/очередь (Celery/RQ + Redis).

5. **Формальный датасет и метрики модели из ТЗ**
   - Нет включённого production-датасета (например, 1200 кейсов).
   - Нет автоматизированного отчёта метрик (precision/recall/F1/AUC) в CI.
